🐳 Docker desde cero

Qué son las imágenes y los contenedores, cómo crear un Dockerfile y cómo levantar una app completa con Docker Compose.

1. ¿Qué es Docker?

Docker es una herramienta para empaquetar una aplicación junto con todo lo que necesita para funcionar (sistema base, lenguaje, librerías, configuración) en una unidad llamada contenedor. Ese contenedor se ejecuta igual en tu computadora, en la de tu compañero y en el servidor.

Se acabó el clásico “en mi máquina sí funciona”: si funciona en el contenedor, funciona en cualquier lugar donde esté instalado Docker.

📄 Dockerfile

Un archivo de texto con la receta: qué imagen base usar, qué archivos copiar y qué comando ejecutar.

🖼️ Imagen

El molde que resulta de construir el Dockerfile. Es de solo lectura y se puede compartir. Ej.: node:20, nginx.

📦 Contenedor

Una instancia en ejecución de una imagen. De una sola imagen puedes crear muchos contenedores.

Contenedor vs. máquina virtual

🖥️ Máquina virtual

Incluye un sistema operativo completo. Pesa gigas y tarda minutos en arrancar.

🐳 Contenedor

Comparte el núcleo (kernel) del sistema anfitrión. Pesa megas y arranca en segundos.

☁️ Registro

Un “GitHub de imágenes” donde se suben y descargan. El más conocido es Docker Hub.

💡 Una analogía: el Dockerfile es la receta, la imagen es el pastel congelado y el contenedor es la porción que sirves. Puedes servir muchas porciones del mismo pastel.

2. Simulador paso a paso

Avanza por los pasos para ver el ciclo de vida: de un Dockerfile a una imagen, y de una imagen a contenedores.

3. Instalación y primer contenedor

En Windows y macOS instala Docker Desktop desde docker.com. En Windows usa el motor WSL 2 (el instalador lo propone). En Linux puedes instalar Docker Engine directamente. 

docker --version            # comprueba que está instalado
docker run hello-world      # descarga y ejecuta un contenedor de prueba

Al ejecutar docker run hello-world, Docker hace tres cosas:

  1. Busca la imagen hello-world en tu computadora. Como no está, la descarga de Docker Hub.
  2. Crea un contenedor a partir de esa imagen.
  3. Lo ejecuta: imprime un mensaje de bienvenida y termina.
⚠️ Si aparece “Cannot connect to the Docker daemon”, es que Docker Desktop no está abierto. Ábrelo y espera a que diga Engine running.

4. Trabajar con imágenes

Las imágenes se identifican por nombre:etiqueta. Si no pones etiqueta, Docker usa latest.

docker pull node:20-alpine      # descarga una imagen
docker images                   # lista las imágenes locales
docker image inspect nginx      # muestra los detalles de una imagen
docker tag mi-app usuario/mi-app:1.0   # le pone otro nombre/etiqueta
docker rmi nginx                # elimina una imagen
docker image prune              # borra imágenes sin usar

🏷️ Etiquetas

node:20, node:20-alpine, node:latest… Usa versiones fijas en lugar de latest para que tu app no cambie sin aviso.

🪶 Alpine y slim

Las variantes -alpine y -slim son mucho más ligeras. Ideales para producción.

🧱 Capas

Una imagen está hecha de capas apiladas. Docker reutiliza las capas que no cambian, por eso las descargas y builds son rápidos.

5. Trabajar con contenedores

Crear y ejecutar

docker run nginx                                # ejecuta en primer plano (Ctrl+C para salir)
docker run -d nginx                             # -d: en segundo plano
docker run -d -p 8080:80 --name web nginx       # puerto 8080 de tu PC → 80 del contenedor
docker run -d -e CLAVE=valor --name app mi-app  # -e: variable de entorno
docker run --rm -it node:20 bash                # --rm: se borra al salir · -it: terminal interactiva

Ver, entrar y detener

docker ps                   # contenedores en ejecución
docker ps -a                # todos, también los detenidos
docker logs -f web          # ver los logs en vivo
docker exec -it web sh      # abrir una terminal dentro del contenedor
docker stop web             # detener
docker start web            # volver a arrancar
docker rm web               # eliminar (debe estar detenido)
docker rm -f web            # detener y eliminar a la vez
Opción de docker runPara qué sirve
-dEjecuta en segundo plano (detached)
-p 8080:80Publica un puerto: tu PC:contenedor
--name webLe da un nombre fácil de recordar
-e CLAVE=valorDefine una variable de entorno
-v datos:/rutaMonta un volumen para guardar datos
--rmBorra el contenedor automáticamente al detenerse
-itModo interactivo con terminal
--network mi-redConecta el contenedor a una red
🔎 Un contenedor vive mientras su proceso principal esté en ejecución. Si el proceso termina (o falla), el contenedor se detiene. Revisa por qué con docker logs <nombre>.

6. El Dockerfile: crea tu propia imagen

Ejemplo para una app de Node.js. El archivo se llama exactamente Dockerfile (sin extensión) y va en la raíz del proyecto:

# 1. Imagen base
FROM node:20-alpine

# 2. Carpeta de trabajo dentro del contenedor
WORKDIR /app

# 3. Copia primero las dependencias (aprovecha la caché)
COPY package*.json ./
RUN npm ci

# 4. Copia el resto del código
COPY . .

# 5. Documenta el puerto y define el comando de inicio
EXPOSE 3000
CMD ["node", "server.js"]
docker build -t mi-app:1.0 .                    # construye la imagen (el punto = carpeta actual)
docker run -d -p 3000:3000 --name web mi-app:1.0

Instrucciones más usadas

InstrucciónQué hace
FROMImagen base de la que partes. Siempre es la primera.
WORKDIRCarpeta de trabajo para las siguientes instrucciones.
COPYCopia archivos de tu proyecto a la imagen.
RUNEjecuta un comando al construir (instalar paquetes).
ENVDefine variables de entorno.
EXPOSEDocumenta en qué puerto escucha la app (no lo publica).
CMDComando que se ejecuta al arrancar el contenedor.
ENTRYPOINTComo CMD, pero más difícil de sobrescribir. Útil para herramientas.

El archivo .dockerignore

Funciona como .gitignore: evita copiar a la imagen archivos innecesarios o secretos.

node_modules
.git
.env
*.log
⚡ Caché de capas: cada instrucción crea una capa. Si una capa no cambió, Docker la reutiliza. Por eso se copia package.json y se ejecuta npm ci antes de copiar el código: si solo cambias el código, no se reinstalan las dependencias.

7. Volúmenes y redes

Al borrar un contenedor, se borra todo lo que guardó dentro. Para conservar datos (por ejemplo, una base de datos) se usan volúmenes.

💾 Volumen

Lo administra Docker. Ideal para bases de datos.
-v datos-db:/var/lib/postgresql/data

📂 Bind mount

Conecta una carpeta de tu PC. Ideal para desarrollo: ves los cambios al instante.
-v ./src:/app/src

🌐 Red

Los contenedores en la misma red se encuentran por su nombre, como si fuera un dominio.

# Volúmenes
docker volume create datos-db
docker volume ls
docker volume rm datos-db

# Redes: la app se conecta a la base de datos usando el host "db"
docker network create mi-red
docker run -d --name db --network mi-red -e POSTGRES_PASSWORD=secreto -v datos-db:/var/lib/postgresql/data postgres:16
docker run -d --name app --network mi-red -p 3000:3000 -e DB_HOST=db mi-app:1.0

8. Docker Compose: varios contenedores a la vez

Escribir todos esos docker run a mano es incómodo. Con Docker Compose describes tu app completa (servicios, puertos, volúmenes y redes) en un archivo compose.yaml y la levantas con un solo comando. 

services:
  app:
    build: .
    ports:
      - "3000:3000"
    environment:
      DB_HOST: db
    depends_on:
      - db

  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: secreto
    volumes:
      - datos-db:/var/lib/postgresql/data

volumes:
  datos-db:
docker compose up -d           # construye y levanta todo en segundo plano
docker compose ps              # estado de los servicios
docker compose logs -f app     # logs de un servicio
docker compose up -d --build   # reconstruye tras cambiar el código
docker compose down            # detiene y borra los contenedores
docker compose down -v         # …y también los volúmenes (¡borra los datos!)
💡 Compose crea automáticamente una red para todos los servicios, así que app se conecta a la base de datos usando el nombre db. Antes se escribía docker-compose (con guion); hoy el comando es docker compose.

9. Docker Hub: compartir imágenes

Docker Hub (hub.docker.com) es a las imágenes lo que GitHub es al código. Allí están las imágenes oficiales (node, nginx, postgres…) y puedes subir las tuyas. 

docker login                                  # inicia sesión con tu usuario de Docker Hub
docker tag mi-app:1.0 usuario/mi-app:1.0      # el nombre debe empezar con tu usuario
docker push usuario/mi-app:1.0                # sube la imagen
docker pull usuario/mi-app:1.0                # descárgala en otra computadora

🐙 Git ↔ Docker

El código y el Dockerfile van a GitHub. La imagen construida va a un registro como Docker Hub.

📦 Otros registros

GitHub Container Registry (ghcr.io), GitLab, AWS ECR, Google Artifact Registry…

🔒 Privacidad

Por defecto, los repositorios de Docker Hub son públicos. No incluyas contraseñas ni archivos .env en la imagen.

10. Buenas prácticas

  • Usa imágenes oficiales y con versión fija (node:20-alpine, no node:latest).
  • Imágenes pequeñas: prefiere variantes -alpine o -slim.
  • Agrega un .dockerignore para no copiar node_modules, .git ni .env.
  • Ordena el Dockerfile de lo que menos cambia a lo que más cambia, para aprovechar la caché.
  • Un proceso por contenedor: la app en uno, la base de datos en otro.
  • Nunca guardes secretos en la imagen. Pásalos con variables de entorno al ejecutar.
  • Guarda los datos en volúmenes, no dentro del contenedor.
  • Limpia de vez en cuando con docker system prune para liberar espacio.
