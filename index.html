🌿 Ramas en Git y GitHub

Qué es una rama, cómo se crea, cómo se une y cómo se trabaja en equipo con Pull Requests.

1. ¿Qué es una rama?

Una rama (branch) es una línea de desarrollo independiente. Te permite trabajar en una nueva funcionalidad o corregir un error sin tocar el código estable, y cuando terminas, unir (hacer merge) esos cambios a la rama principal.

Técnicamente, una rama en Git es solo un puntero ligero a un commit. Cada vez que haces un commit en esa rama, el puntero avanza automáticamente. Por eso crear ramas en Git es instantáneo y barato.

📌 main

La rama principal. Normalmente contiene el código estable, listo para producción. (Antes se llamaba master.)

🧭 HEAD

Un puntero especial que indica en qué rama estás ahora. Los nuevos commits se agregan donde apunta HEAD.

🌱 Rama de trabajo

Ramas como feature/login o fix/navbar donde desarrollas cambios aislados.

Avanza por los pasos para ver cómo evoluciona el historial de commits.

3. Comandos básicos de ramas

Ver ramas

git branch          # ramas locales (la actual con *)
git branch -a       # locales y remotas
git branch -v       # con el último commit de cada una

Crear y cambiar de rama

git branch feature/login        # crea la rama (no te mueve)
git switch feature/login        # cambia a la rama

git switch -c feature/login     # crea y cambia en un solo paso

# Forma clásica (sigue funcionando)
git checkout feature/login
git checkout -b feature/login

Renombrar y eliminar

git branch -m nuevo-nombre      # renombra la rama actual
git branch -d feature/login     # elimina (solo si ya se unió)
git branch -D feature/login     # elimina forzando (¡pierdes commits no unidos!)
💡 Antes de cambiar de rama, haz commit de tus cambios o guárdalos temporalmente con git stash. Luego los recuperas con git stash pop.

4. Unir ramas: merge y conflictos

Para traer los cambios de una rama a otra, te colocas en la rama destino y haces merge de la rama origen:

git switch main
git merge feature/login

⏩ Fast-forward

Si main no tuvo commits nuevos desde que creaste la rama, Git simplemente adelanta el puntero. No se crea un commit extra.

🔀 Merge de tres vías

Si ambas ramas avanzaron, Git crea un commit de merge que tiene dos padres y combina los cambios.

📐 Rebase (alternativa)

git rebase main reaplica tus commits encima de main, dejando un historial lineal. No lo uses en ramas compartidas ya publicadas.

¿Y si hay un conflicto?

Ocurre cuando las dos ramas modificaron las mismas líneas de un archivo. Git pausa el merge y marca el archivo así:

<<<<<<< HEAD
<h1>Bienvenido</h1>
=======
<h1>Hola, usuario</h1>
>>>>>>> feature/login
  1. Abre el archivo y decide qué versión dejar (o combina ambas).
  2. Borra los marcadores <<<<<<<, ======= y >>>>>>>.
  3. Marca el conflicto como resuelto y termina el merge:
git add index.html
git commit                 # completa el merge

git merge --abort          # o cancela y vuelve al estado anterior

5. Ramas remotas (Git ↔ GitHub)

Tus ramas locales viven en tu computadora. Para compartirlas, las subes a un remoto (normalmente llamado origin, que apunta a tu repositorio en GitHub). 

# Subir una rama nueva y vincularla (-u = upstream)
git push -u origin feature/login

# Después basta con:
git push

# Traer información de ramas remotas
git fetch                       # descarga sin modificar tu trabajo
git pull                        # fetch + merge en la rama actual

# Trabajar en una rama que creó otra persona
git switch feature/pagos        # Git la crea a partir de origin/feature/pagos

# Eliminar una rama en GitHub
git push origin --delete feature/login
🔎 origin/main es una rama de seguimiento remoto: una copia local de cómo estaba main en GitHub la última vez que hiciste fetch o pull.

6. GitHub y los Pull Requests

Un Pull Request (PR) es una solicitud en GitHub para unir tu rama a otra (normalmente main). Es el lugar donde el equipo revisa, comenta y aprueba los cambios antes del merge.

Crear un PR

Tras hacer git push de tu rama, GitHub muestra el botón “Compare & pull request”. Elige la rama base (main) y la de comparación (tu rama), escribe un título y descripción.

Revisión

Los compañeros dejan comentarios en líneas específicas, aprueban o piden cambios. Cada nuevo push a tu rama actualiza el PR automáticamente.

Opciones de merge

Merge commit (conserva todo), Squash and merge (un solo commit) o Rebase and merge (historial lineal).

También puedes crear PRs desde la terminal con GitHub CLI:

gh pr create --base main --title "Agrega login" --body "Descripción del cambio"
gh pr list
gh pr merge 12 --squash --delete-branch
🛡️ En Settings → Branches puedes crear reglas de protección para main: exigir PR, aprobaciones mínimas o que pasen los tests antes de unir.

7. Flujo de trabajo completo (GitHub Flow)

  1. Actualiza main: git switch main y git pull.
  2. Crea tu rama: git switch -c feature/carrito.
  3. Trabaja y haz commits: git add . y git commit -m "Agrega carrito".
  4. Sube la rama: git push -u origin feature/carrito.
  5. Abre un Pull Request en GitHub hacia main.
  6. Revisión y ajustes: corrige lo que te pidan y vuelve a hacer push.
  7. Merge del PR en GitHub.
  8. Limpia: git switch main, git pull y git branch -d feature/carrito.

8. Buenas prácticas

  • Una rama por tarea. Ramas pequeñas y de vida corta son más fáciles de revisar y unir.
  • Nombres descriptivos con prefijo: feature/, fix/, hotfix/, docs/, refactor/.
  • No trabajes directo en main. Usa siempre una rama y un PR.
  • Sincroniza seguido con main (merge o rebase) para evitar conflictos grandes.
  • Commits claros: mensajes que expliquen qué y por qué.
  • Borra las ramas ya unidas para mantener el repositorio ordenado.
